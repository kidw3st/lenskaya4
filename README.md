# ЖК «Ленская» — сайт

Многостраничный сайт жилого комплекса бизнес-класса, реализованный по спецификации
[Lenskaya_UX_UI_Spec.md](Lenskaya_UX_UI_Spec.md) (актуальная версия документа — 1.6).

**Основной продукт проекта — земельные участки под застройку.** Жилые корпуса — не второй
продукт в продаже, а **готовый проект, показанный инвесторам и партнёрам**: раздел сохранён
в полном объёме (709 лотов, планировки, фильтры), но подаётся как витрина проработки.

**Цены на сайте не публикуются.** Ни по участкам, ни по лотам корпусов: везде «Цена по запросу»
и телефон. Что нужно знать перед правками — см. [Цены](#цены) ниже.

Бриф на недостающие изображения — [Бриф_на_изображения.md](%D0%91%D1%80%D0%B8%D1%84_%D0%BD%D0%B0_%D0%B8%D0%B7%D0%BE%D0%B1%D1%80%D0%B0%D0%B6%D0%B5%D0%BD%D0%B8%D1%8F.md).

**Стек:** чистые HTML + CSS + JavaScript. Сборка не нужна — папка `site/` кладётся на любой
веб-сервер и работает как есть. Никаких зависимостей и внешних CDN.

## Живой сайт

**https://kidw3st.github.io/lenskaya4/**

Опубликован на GitHub Pages из ветки `gh-pages`, в которую выкладывается
содержимое папки `site/`. Ветка `main` — исходники, спецификация и инструменты.

### Обновить опубликованную версию

Перед выкладкой поднимите версию ассетов, иначе браузер вернувшегося посетителя
может взять новый HTML и старый CSS/JS из кэша (на GitHub Pages статика
кэшируется примерно на 10 минут):

```bash
node tools/bump-assets.mjs
```

Затем закоммитьте и выложите:

```bash
git subtree push --prefix site origin gh-pages
```

Одна команда после коммита в `main`. Сборка не нужна — в `gh-pages` уходит
ровно то, что лежит в `site/`.

Автоматической выкладки через GitHub Actions сейчас нет: у токена workflow
в этом репозитории нет права включать Pages (`Resource not accessible by
integration`). Если она понадобится, включите в настройках репозитория
**Settings → Actions → General → Workflow permissions → Read and write**,
после чего можно добавить workflow, публикующий `site/` в `gh-pages`.

## Быстрый старт

```bash
node tools/serve.mjs
```

Откроется на `http://localhost:4173`. Сервер нужен только для локального просмотра: страницы
загружают данные каталогов через `fetch`, а он не работает с `file://`.

## Команды

```bash
node tools/check.mjs
```

Проверяет: битые локальные ссылки, отсутствующие медиа, количество `H1`, наличие `alt`,
обязательность и отсутствие предзаполнения чекбокса согласия, наличие honeypot,
наличие дисклеймера рядом с визуализациями застройки, разделение каталогов.

```bash
node tools/gen-data.mjs      # пересобрать демо-данные
node tools/gen-assets.mjs    # пересобрать медиаплейсхолдеры
node tools/gen-sitemap.mjs   # пересобрать sitemap.xml
```

Генераторы детерминированы: повторный запуск даёт тот же каталог.

## Что важно не сломать

**1. Участки и квартиры — два разных продукта, участки главнее.**
Отдельные каталоги, отдельные модели данных, отдельные типы карточек, отдельные CTA.
Карточка участка — горизонтальная 3:2 с бронзовой рамкой и меткой «Участок». Карточка
квартиры — вертикальная 4:5 без рамки, оливковый акцент. Ни при каком сочетании фильтров,
сортировок и блоков «похожие» лоты одного типа не попадают в выдачу другого.
`tools/check.mjs` следит за этим.

Приоритет передаётся весом кнопок: у участков — заливная бронзовая (`btn--land`),
у квартир — контурная (`btn--secondary`). Порядок «участки → квартиры» соблюдается
в меню, мобильном меню, подвале, вкладках избранного, переключателях типа объекта
в формах и на странице 404.

**2. Дисклеймер под визуализациями застройки.**
Под каждым изображением дома или квартиры в разделе участков стоит текст:

> Иллюстративная визуализация. Итоговый вид определяется выбранным проектом застройки.

Он лежит в поле `disclaimer` каждого типового проекта в `data/house-projects.json`
и не может быть пустым — проверка падает. Дисклеймер выводится в карточке, в сетке,
в lightbox и в модальном окне проекта.

**3. Цены не публикуются.**
Ни в каталоге участков, ни в проекте корпусов. Везде «Цена по запросу» и телефон.
Подробности и как включить обратно — раздел [Цены](#цены). Лоты с `is_published: false`
не попадают ни в выдачу, ни в sitemap, ни в фиды.

**4. Согласие на обработку ПДн — активное действие.**
Чекбокс нигде не предзаполнен, отправка формы без него блокируется.

**5. Интро — не длиннее 6 секунд.**
Показывается один раз за сессию (`sessionStorage`), кнопка «Пропустить» доступна с нулевой
секунды и с клавиатуры, при `prefers-reduced-motion` сокращается до статичного кадра.

**6. Цвета — только через семантические токены.**
В компонентах и разметке нельзя писать `#hex` или `var(--c-milk)` — иначе тёмная тема
сломается. Используйте `--bg`, `--surface`, `--text`, `--text-2`, `--line`, `--accent`,
`--bronze` и т. д. из `tokens.css`. Для текста на всегда-тёмных поверхностях (подвал,
тёмные секции) есть отдельные токены `--on-dark`, `--on-dark-2`, `--bronze-on-dark`.

## Цены

По решению Заказчика от 03.09.2026 **цены на сайте не публикуются вообще** — покупатель
узнаёт стоимость по телефону. Это касается обоих каталогов.

Что это значит на практике:

- вместо суммы выводится «Цена по запросу» и номер `+7 (342) 200-00-00`;
- фильтров и сортировок по цене нет ни в каталоге участков, ни в проекте корпусов;
- переключателя «за участок / за сотку» нет;
- строки «₽ за сотку» и «₽ за м²» скрыты;
- в блоке «Что входит в стоимость» на карточке участка вместо суммы стоит телефон.

**Данные о ценах при этом сохранены.** Поля `price`, `price_per_are` и `price_per_sqm`
остаются в `data/land.json` и `data/flats.json` — они нужны CRM и будущим выгрузкам
в агрегаторы. Они просто не выводятся.

### Как включить публикацию обратно

Два флага в начале `site/assets/js/site.js`:

```js
LK.LAND_PRICE_PUBLIC = false;  // земельные участки
LK.FLAT_PRICE_PUBLIC = false;  // лоты жилых корпусов
```

Поставьте нужный в `true` — цены вернутся в карточки, в каталог и на страницу лота.
Фильтры и сортировки по цене флагом **не возвращаются**: их разметка удалена из
`land.html` и `flats.html`, а конфиги — из `assets/js/catalog.js`. Смотрите там комментарии
рядом с `ranges` и `sorters`.

После включения цен вернётся и правило «цена всегда сопровождается датой актуальности»
(поле `updated_at`) — оно уже реализовано в коде и включится вместе с флагом.

## Светлая и тёмная темы

Кнопка солнце/луна в шапке на всех страницах.

1. По умолчанию сайт следует системной настройке (`prefers-color-scheme`).
2. Явный выбор пользователя сохраняется в `localStorage` под ключом `lenskaya_theme`
   и имеет приоритет над системной настройкой.
3. Пока выбор не сделан, смена системной темы применяется на лету.
4. Атрибут `data-theme` проставляется маленьким скриптом в `<head>` **до первой отрисовки** —
   поэтому нет вспышки чужой темы при загрузке.
5. Обе темы проверены на контраст: весь текст ≥ 4,5:1 (крупный ≥ 3:1).
6. Подвал и тёмные секции остаются тёмными в обеих темах — это часть фирменного стиля.
7. Чертежи и схемы остаются светлыми (это документы), в тёмной теме слегка приглушаются
   фильтром `--doc-dim`.

## Анимации

Слой движения вынесен в `assets/css/motion.css` + `assets/js/motion.js` и **необязателен**:
без него сайт полностью работоспособен, весь контент виден.

Правила, которые нельзя нарушать при доработке:

1. **По умолчанию всё видно.** Классы, скрывающие элемент до анимации
   (`.m-item`, `.m-media`, `.img-pending`, `.hero.is-anim`), навешивает только JS.
   Отключён JS или скрипт упал — контент на месте. Есть страховка: через 3 секунды
   всё принудительно показывается.
2. **Анимируются только `opacity` и `transform`.** Иначе браузер пересчитывает
   макет на каждом кадре и появляется дрожание.
3. **`prefers-reduced-motion: reduce` выключает движение целиком** — и в CSS,
   и в JS (наблюдатели не создаются, классы не навешиваются).
4. **Ничто не смещает контент.** Анимация появления не влияет на высоту блока,
   поэтому CLS не растёт.

Что именно анимировано: каскадное появление секций и карточек при скролле,
вход героя по строкам с наплывом фона, лёгкий параллакс фона героя,
проявление изображений по мере загрузки, анимация чисел в блоке «Ключевые цифры»,
отклик сердца избранного и счётчика в шапке, поворот иконки темы,
стрелка на главных призывах, вход модалок и lightbox, каскад мобильного меню.

## Удобство

- Полоса прогресса чтения в шапке.
- Кнопка «Наверх» после 900 px прокрутки; не налезает на липкую панель лота.
- Липкая строка результатов в каталогах на мобильном: количество найденного
  и кнопка «Фильтры» всегда под рукой.
- Предзагрузка страниц по наведению — переходы ощущаются мгновенными.
  Отключается при `saveData` и на медленных сетях.
- Копирование телефона, почты и адреса на странице контактов с подтверждением.
  Есть запасной путь, если Clipboard API недоступен.

## Что подключается на этапе разработки

Сейчас это работающий прототип на демо-данных. Для боевого запуска нужно:

- **Backend для форм.** Сейчас отправка эмулируется и лид пишется в `localStorage`
  (`lenskaya_leads`) — см. `site/assets/js/site.js`, блок «Демонстрационная отправка».
  Заменяется на `POST /api/lead` с серверной валидацией и передачей в CRM (раздел 8.1 спецификации).
- **CMS.** Данные каталогов лежат в JSON; поля соответствуют модели данных из раздела 4
  спецификации, так что переносятся в админпанель один в один.
- **Яндекс Карты.** Карты сейчас — статичные превью с кнопкой «Показать карту»
  (`data-map-activate`). Точка подключения API размечена.
- **Яндекс Метрика.** События уже отправляются в `window.dataLayer` через `LK.track()` —
  см. список событий в разделе 9.4 спецификации. Счётчик подключается после согласия на
  аналитические cookie.
- **Шрифты.** Сейчас системный стек. Продакшен — лицензированные TT Ramillas (display)
  и TT Commons Pro (интерфейс); подменяются двумя переменными в `assets/css/tokens.css`.
- **Медиа.** 134 SVG-плейсхолдера в фирменной палитре, каждый подписан ID слота из реестра
  (раздел 5 спецификации). Заменяются на утверждённые Заказчиком материалы в AVIF/WebP.

## Проверено

- 20 страниц, по одному `H1` на страницу, консоль без ошибок.
- Нет горизонтального переполнения на 320, 375 и 768 px.
- Оба каталога фильтруют, сортируют и разбиваются на страницы; выдачи не смешиваются.
- Сквозной сценарий: участок → визуализация застройки → заявка с `object_type=land`,
  `object_id` и `house_project_id`.
- Формы: валидация телефона и почты, обязательное согласие, сохранение введённых данных
  при ошибке, success с контекстным переходом в нужный каталог.
- Избранное: две вкладки, счётчик, состояние «лот больше не доступен», пустые состояния.
- Тач-таргеты не меньше 44 px, фокус с клавиатуры виден, `prefers-reduced-motion` отключает анимацию.

Демо-данные (цены, площади, кадастровые номера, сроки) — синтетические. Публикация реальных
значений возможна только после письменного утверждения Заказчиком, см. раздел 11 спецификации.
